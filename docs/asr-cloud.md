# 云 ASR（阿里云百炼 Paraformer）

仅用于**没有站内字幕**的视频。有字幕的视频走 B 站字幕，**不花钱**。

---

## 一、为什么走云端而不是本地

实测数据（`scripts/measure_asr_memory.py`、`bench_asr_steady.py`）：

| 方案 | 内存 | 速度 | 成本 |
| --- | --- | --- | --- |
| 本地 FunASR | **峰值 5.3 GB**（服务器至少 4核8G） | CPU RTF ≈ 0.17 | 4核8G ≈ 450 元/年（常驻） |
| **云端 Paraformer** | 几乎不占（只有 HTTP） | 11 秒转完 9 分钟音频 | **0.288 元/小时**，按量付费 |

**关键结论**：本地那 5.3 GB 里，**模型权重不是大头** ——
换大模型/小模型内存几乎一样（4.19 vs 4.31 GB），
说明占内存的是 FunASR 运行时 + PyTorch 本身。

所以对"一个人偶尔用"的场景，云端明显更省：**不为闲置付费**，
服务器也能用最低配（2核2G 就够，因为不做本地推理）。

### 顺便：去掉时间戳省了 58% 的输入 token

时间戳占 prompt 的 **58%**（实测 19,193 → 8,108 token）——
每段都要渲染一个 `[HH:MM:SS]`，而很多段只有一句话。
产物本身就是总结、不需要跳回原视频，所以**默认不再带时间戳**。
详见 `vd/summarize.py` 的模块说明。

## 二、必须绕开的坑：B 站 CDN 校验 Referer

阿里云 Paraformer **只接受公网可访问的 URL**（官方 FAQ 原文：
"不支持 Base64 编码方式的音频……不支持识别二进制流，也不支持直接识别本地文件"）。

而 B 站音频链接**外部拉不到**（实测）：

```
裸请求（无 UA、无 Referer）   → HTTP 403
带 Referer: bilibili.com      → HTTP 200，61.4 MB
```

直接提交 B 站链接给阿里云 → `FILE_403_FORBIDDEN`（实测过两次）。

**所以流程必须是**：

```
你的服务器                          阿里云
   │  1. 带 Referer 下载 B 站音频
   │  2. 存进 data/relay，生成随机 token
   │  3. 交出 http://<公网地址>/relay/<token> ──►
   │                                            4. 阿里云来下载
   │                                            5. 转写（句级 + 词级时间戳）
   │◄────────────────────────────────────────────
   │  6. 取回结果后**立即删文件**并注销 token
```

`VD_PUBLIC_BASE_URL` 就是第 3 步里"阿里云能访问到的根地址"。
配置方法见 [deploy.md](deploy.md)。

```
  音频总长            ：538 秒

```

**验证掉的三个未知**：

| 项 | 结果 |
| --- | --- |
| 阿里云能否从我们的中转 URL 拉到音频 | ✅ 能 |
| 时间戳形态 | ✅ 毫秒，句级；`segs[i].start` 换算后单调递增 |
| 计费口径 | ✅ `content_duration` 只算语音（本例 **57%**，停顿确实不计费） |

### 这次验证抓到一个真实的架构 bug

第一版把 token 存在**进程内字典**里，实测立刻炸：

```
verify 脚本进程：publish() 写自己的内存
服务进程：        /relay 路由查自己的内存 → 空 → 403
```

服务日志原文：`严格模式：无进行中的转写任务，拒绝中转请求`。
阿里云因此拿到 `FILE_403_FORBIDDEN`。

**发布 token 的进程和响应 `/relay` 的进程不是同一个。**
生产环境里 worker 与服务同进程时侥幸能跑，但**服务一重启就丢**。

修复：token 注册表落盘（SQLite `data/relay/registry.sqlite3`），
跨进程共享、重启不丢。回归测试
`test_registry_is_visible_across_processes` 用**独立子进程**读父进程发布的
token —— 如果退回内存字典，它会失败。

## 四、安全：`/relay` 是免登录的公开路由

必须如此 —— 阿里云没有本站的登录凭据。

| 措施 | 说明 |
| --- | --- |
| token 不可枚举 | `secrets.token_urlsafe(24)` |
| **一次性** | 取回结果后立即删文件 + 注销 token |
| 短命 | TTL 默认 2 小时（验证时可调短） |
| 无路径拼接 | 文件名必须与 token 完全一致，杜绝路径穿越 |
| **严格模式** | `VD_RELAY_STRICT=1` 时，无进行中任务一律 403 |
| 可选 UA 白名单 | `VD_RELAY_UA_PREFIX`，收窄来源 |

### ⚠️ 一个做不到的事：IP 白名单

"只允许阿里云 IP 访问"**做不到**：

- 走 Cloudflare 隧道时，服务看到的对端是 **Cloudflare 边缘节点**，不是阿里云；
- 即使直连，阿里云拉取用的出口 IP 也不固定，写死了反而挡住真正的请求。

所以真正的防护是"**不可猜测 + 短命 + 一次性**"，不是来源限制。

### ⚠️ 另一个部署时要知道的副作用

`is_local()` 只看**对端地址**（不看 Host 头，这是对的，Host 可伪造）。
但如果你用 `--host 0.0.0.0` 启动，然后**从本机浏览器**访问公网/隧道地址，
数据包出去再回来，对端地址**仍是 `127.0.0.1`** → **仍然免登录**。

这是"本人本机免登录"的设计取舍。含义是：
**你在本机测"远程是否要登录"时，测出来的可能不是真实结果。**

## 五、质量：热词是必要的

上面那次转写里，专有名词明显出错：

```
"DeepSeek" → "dpc car" / "dc harness" / "dpc car官方桌面端"
```

这是 ASR 的固有问题，靠**热词表**解决：

- 本地：`data/hotwords.json`（`vd/hotwords.py`，现有 9 条 BUILTIN）
- 云端：Paraformer 支持 `vocabulary_id`（需先在控制台建热词表）

**对术语密集的视频（如缠论、技术教程）建议建热词表**，
否则关键概念会被转错，而总结会忠实地把错误放大。
