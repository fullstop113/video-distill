## 一、已确认的事实（协议原文）

必须先把"什么是确定的"与"什么是猜测"分开。以下都是原文，不是解读：

| # | 条文 | 原文要点 |
| --- | --- | --- |
| 1 | §4.2.11 | 未经哔哩哔哩事先明确书面许可，**以任何方式（包括但不限于机器人软件、蜘蛛软件、爬虫软件等任何自动程序、脚本、软件）和任何理由**自行或委托他人、协助他人获取平台的服务、内容、数据 |
| 2 | §1.2 | 哔哩哔哩所提供的服务**仅供用户非商业性使用**；未经事先书面同意，不得以商业性目的使用 |
| 3 | §2.3 | 如果哔哩哔哩发现或**有合理理由认为使用者并非账号初始注册人**，有权在不通知的情况下暂停或终止向该注册账号提供服务，**并注销该账号** |
| 4 | §2.6.4 | 不从事"窃取、盗用他人的哔哩哔哩账号"等行为 |
| 5 | §2.7 | 哔哩哔哩有权对违反上述条款的用户作出**禁止注册及/或封号**的处理 |
| 6 | §6.5 | 未经哔哩哔哩许可，任何单位和个人不得私自**转载、传播**和提供观看服务 |
| 7 | §4.1.6 | 用户使用服务应遵守《信息网络传播权保护条例》 |

### 1.1 一个必须说清的点：自动化取数**本身就违约**，与公开/私有无关

第 1 条的限制是"**任何理由**"，并未区分个人学习与对外服务。
所以本项目即使只自己用，也已落在 §4.2.11 的字面范围内。
"公开 vs 私有"决定的**不是"是否违约"，而是"违约之外还会不会产生别的责任"**。

## 二、决策 ①：暴露范围 = **邀请制小圈子（方案 B）**

**已选定**，理由与边界：

| 边界 | 具体做法 |
| --- | --- |
| 不对外开放注册 | 无注册入口；使用者由管理员手工加入邀请名单 |
| 不公开收录内容 | 不做公开的"视频库"页面，不提供站内搜索 |
| 不对外分发逐字稿 | 产物仅供提交者本人查看/下载，不提供公开分享链接 |
| 非商业使用 | 不收费、不投放广告、不用于商业模型训练（对应 §1.2） |
| 显著免责声明 | 见 `src/vd/disclaimer.py`，出现在登录页与每份产物头部 |

**未选** C（公开服务）：会同时触发著作权责任与 ICP 备案义务，而边际收益（多几个用户）
远小于边际责任。

## 三、决策 ②：接受"账号连坐"，并写入免责声明

**已选定：接受并明确告知。**

依据 §2.3 / §2.6.4：服务把使用者的 SESSDATA 集中到一台机器上，以使用者身份发起自动化请求。
风险不只在"泄露"，更现实的是**风控识别出多个账号来自同一台机器后的集中处置**——
受影响的不只是管理员账号。

已落地的缓解措施：

1. **每个使用者用自己的凭据**，不允许跨 UID 复用会话；
2. **按凭据账号独立限速与并发**，不做"全局共享一个会话"的高频请求；
3. **免责声明明确写出**"你使用的账号存在被处置的风险，请自行评估"；
4. **支持随时删除凭据**，删除后立即无法再以该身份访问。

## 四、决策 ③：大号 / 小号分离（管理员仅用小号凭据取数）

**已选定并已落地为代码强约束。**

### 4.1 为什么这条最重要

§2.7 的处罚权是**按账号**的：谁被用来发自动化请求，风险就落在谁头上。
所以把"管理员身份"与"取数身份"分开，可以让大号完全不沾染抓取行为。

### 4.2 角色定义

| 角色 | 环境变量 | 凭据是否落盘 | 是否参与取数 | 配额 |
| --- | --- | --- | --- | --- |
| **管理员大号** | `VD_OWNER_BILI_UID` | ❌ 绝不 | ❌ 绝不 | 不限 |
| **操作号小号** | `VD_OPERATOR_BILI_UID` | ✅ 唯一 | ✅ 唯一 | 不限 |
| 其他管理员 | `VD_ADMIN_UIDS` | — | ❌ | 不限 |

> 注意：**"谁是管理员"与"用哪个号取数"是两件独立的事。**
> 大号与小号**都是管理员、都不限配额**；区别只在于谁的凭据用于取数。

### 4.3 代码如何强制（不是靠自觉）

`src/vd/credentials.py` 实现**白名单**，而不是"优先选小号"：

| 情况 | 行为 |
| --- | --- |
| 未配置 `VD_OPERATOR_BILI_UID` | **拒绝取数**并提示配置 |
| 操作号 == 管理员大号 | **拒绝**并说明隔离失效 |
| 操作号凭据未登录 | **拒绝**并提示扫码 |
| 已落盘凭据不是操作号 | 拒绝使用，并 warning 建议清理 |

为什么不用"优先选"：如果写成"优先小号、否则用第一个"，
那么大号一旦登录，代码会**静默地开始用大号抓取**，且没有任何报错。
白名单把这种沉默失败变成明确拒绝。

回归测试：`tests/test_credential_policy.py`（11 条），
其中 `test_owner_credentials_never_used_for_scraping` 直接钉住这个不变量。

### 4.4 一个副作用（需要接受）

`scripts/hit_rate.py` 的 `--source history` 取的是**当前凭据账号**的观看历史。
既然取数只能用操作号，那它拿到的是**小号的**观看历史，**不是大号的**。
要用大号看过的视频做样本，只能手工传 `--bvid`。
这正是隔离生效的证明，不是 bug。

## 五、决策 ④：部署 = 云 GPU，但**不需要常驻**（对方案 §5.3② 的修正）

**已选定云部署。** 但方案里的成本估算（¥1,000-3,000/月）建立在"GPU 7×24 常驻"假设上，
而本项目的实测数据不支持这个假设。

### 5.1 为什么仍然需要 GPU

关键实测事实：**站内字幕命中率只有 60%**，剩下 40% 必须下载音频自行转写。
本地 ASR（FunASR/Paraformer）要跑神经网络推理，**DeepSeek 是文本模型、不收音频**，
替代不了这一步。所以 GPU 的定位是**兜底**，不是主干。

60% 走字幕 = **零 GPU**；40% 走 ASR = 约 0.7 分钟 GPU / 小时音频。

### 5.2 实测成本（公开报价，2026-07）

来源：[2026 年六家主流算力平台深度对比](https://www.jygpu.com/article/726.html)

| GPU | 阿里云 | 腾讯云 | AutoDL | 极智算 |
| --- | --- | --- | --- | --- |
| 4090 | ¥5-6/卡时 | ¥4-5/卡时 | ¥3-5/卡时 | **¥1.96/卡时** |
| 4090 月租 | — | — | — | ¥1,341/月 |

按实测 RTF 0.0108 推算：每天 20 个视频（约 5 小时音频）只需 **约 3.5 分钟 GPU**。
按 ¥1.96/卡时、按量计费 → **约 ¥3.4/月**。

### 5.3 推荐架构：Web 与 GPU 分离

| 部分 | 配置 | 在线要求 | 估算成本 |
| --- | --- | --- | --- |
| Web + 队列 + 字幕路线 | 便宜 CPU 小机器 | 7×24 | ¥30-60/月 |
| ASR 兜底（那 40%） | 按量 GPU，用完即关 | 仅需要时 | 约 ¥3-30/月 |

**不要**租一台 GPU 常驻跑 Web —— 那会把成本推回方案里估算的 ¥1,000+/月，
而 GPU 在 99% 的时间里是空闲的。

> ⚠️ 上述均来自**公开报价文章**，不是我们从供应商 API 取到的实时价格。
> 真正下单前需要按实际平台页面复核。

### 5.4 成本汇总（每小时视频）

| 项目 | 实测值 |
| --- | --- |
| DeepSeek 总结（flash，空闲时段，map-reduce 放大 2.5 倍） | **¥0.042** |
| `deepseek-v4-pro` 同口径 | ¥0.171（贵约 4 倍） |
| ASR 兜底（仅 40% 的视频走这条） | 约 ¥0.0004（按 ¥1.96/卡时、0.7 分钟/小时） |
| 站内字幕路线 | ¥0 |

**结论：LLM 与 GPU 的按量成本都极低，真正花钱的是"让服务 24 小时在线"这件事本身。**

### 5.5 模型选择：`deepseek-flash`

**已选定。** 2026 实测（`scripts/deepseek_probe.py`）：

| 请求的模型名 | 实际服务模型 | 说明 |
| --- | --- | --- |
| `deepseek-flash` | `deepseek-flash` | 价目表在列 |
| `deepseek-v4-pro` | `deepseek-v4-pro` | 贵约 4 倍 |
| `deepseek-chat`（旧名） | `deepseek-flash` | 能调，但语义不明确，**不要再依赖** |
| `deepseek-reasoner`（旧名） | `deepseek-flash` | 同上 |

**另一个实测坑**：`max_tokens=8` 时 flash/v4-pro 返回**空字符串**——
思考模式默认开启，8 个 token 全花在思考上。P2 必须显式关闭思考模式
（`.env` 已加 `DEEPSEEK_THINKING=disabled`）。

当前定位为**本机/内部使用的邀请制工具，不向公众提供互联网信息服务**，因此未办理 ICP 备案。

- 免责声明中的备案条款需同步改写（`vd.disclaimer` 已预留 `public_service` 开关）。
